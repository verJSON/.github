# 0165 — Preserve generated changelog runner boundaries in consumer policy

- **Date:** 2026-09-05
- **Status:** Accepted
- **Issue:** [#1261](https://github.com/Verjson/.github/issues/1261)

## Context

Verjson/verjson-ci#29 generated its adoption from immutable canonical source but
consumer hosted-selector policy rejected the default PR gate and release selectors.
The PR gate deliberately runs PR-authored verification on disposable `ubuntu-24.04`
with a read-only token and checkout credential persistence disabled. Moving that job
to a configurable persistent lane just to satisfy the cost-routing policy would
reverse the isolation invariant. The release selector wraps the exact JSON expression
already approved for reusable runner inputs; its routing did not introduce new behavior.

## Decision

Preserve the generated bytes and runner behavior. Consumer policy exempts only the
complete canonical hosted PR-gate document from its Tier B literal-Linux cost rule.
The recognizer fixes every workflow, permission, job, checkout and executable step
field, plus the hosted label and timeout; it checks scalar types as well as values.
Additional jobs, permissions, environment, defaults, checkout inputs or steps withdraw
the exception. It trusts neither a filename nor a generated-file comment. It is a
reviewed safe shape, not proof that a consumer ran the generator. Other selector
checks continue to apply, and the exception does not apply to canonical policy mode.

Admit exactly the existing release JSON expression wrapped in `fromJSON`, preserving
its organization/non-organization routing. Do not broaden the expression grammar.
Explicit `--untrusted-runner` overrides retain the existing literal-label validation
and normal consumer policy; labels alone are not an attestation of runner isolation.

## Verification and adoption

Regression tests generate real PR-gate and release callers at one immutable source
SHA, run consumer policy, and reject changes to executable fields, permissions,
scalar types, unknown expressions and metered selectors. Run the generated contract
test and the exact pinned changelog release command in a disposable clean fixture;
verify its commit, annotated tag and selected fragment tree without pushing.

Verjson/verjson-ci owns adoption of the newly merged policy SHA and generated callers.
This repository changes no consumer checkout or release state. A future generator
change to the safe PR-gate shape must update this recognizer and its generator-output
regression together, so checkout pins and executable steps cannot drift silently.

## 2026-10-20 amendment — The PR gate's runner is bound to its header

The generated contract test checked the PR gate's header, job count and cache
order, but not its `runs-on`. An adopter could hand-edit a persistent
`[self-hosted, general]` runner under a bare header. That sends pull-request code to
a persistent host, which is the boundary this decision preserves. An adopter could
also record `--untrusted-runner x` in the header over a different body. The header
now records `--untrusted-runner` when it is used, so the contract test derives the
one admissible runner from it: `ubuntu-24.04` when the header records no option,
and exactly the recorded labels, in order, when it does. The `changelog-contract`
job must name that runner on its own `runs-on` line. The file may name no other
runner and use no YAML merge key, and it must carry exactly one generator header.

`--untrusted-runner` keeps admitting self-hosted labels. A dedicated ephemeral pool
is a permitted target under [ADR 0235](../0235-public-pull-request-code-uses-ephemeral-runners/README.md),
and this decision already records that labels are not an attestation of isolation.
A generator-side refusal could not verify isolation either; it would only remove
the reviewed exception that `generated-changelog-selector-policy.test.py` and
adopters (for example verjson-ai-gguf ADR 0007) rely on. The selection is now
bound instead. It is visible in the reviewed header, it cannot diverge from the
body, and consumer selector policy still applies to it.
