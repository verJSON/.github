## Collapse identical Renovate transition rows instead of refusing the pull request

Renovate changelog attribution now records a package transition once when Renovate's update table lists it in several rows, as it does when one image is bumped in more than one file or build stage. Verjson/verjson-ci#290 failed `renovate-changelog / attribute` because `node` 26.10.0-alpine3.23 → 26.12.0-alpine3.23 appeared twice. Rows for the same package with a different from or to version stay separate, the 50-row bound still counts every row before collapsing, and package and version spellings are compared exactly. Adopters receive the fix when they regenerate their callers at a contract SHA that includes it. ADR 0104's 2026-10-21 amendment records the change.

## Document the GAR provider rotation that must precede a publisher repin

The container candidate adoption guide now says to rotate a GAR destination's Workload Identity provider to the new contract SHA, and to have that rotation reviewed, before regenerating at that SHA. It gives the read-only `describe`, a SHA-only `update-oidc`, and two read-back diffs that must be empty. It also explains why neither a partial nor a repeated full rerun can repair a failed candidate publication: push a new commit instead.

## Run the required-reviewer ruleset check in the daily conformance audit

The daily `org-ruleset-conformance.yml` audit now runs `required-reviewer-ruleset.py check`, so a deleted, edited, duplicated or undeclared `*-sensitive-path-admin-review` ruleset fails the next scheduled run instead of staying invisible until someone runs `check` by hand (ADR 0210 rollout step 4).

## Move the CLI Projects required workflow to v4.2.0

The CLI Projects required workflow now runs its protected lanes on `node-ci-protected.yml` at v4.2.0 and admits only the push-only `ci.yml` caller generated at the v4.2.0 contract release (`node-ci.yml@a89fe1f0`, sha256 `d23be004…`) instead of the v3.0.2 caller (`9e4ca97c…`), so `Verjson/verjson-cli-projects` can adopt the current release without `contract-version.py verify` reporting `PIN_MISMATCH`. Organization ruleset 21830367 keeps running the previous revision until it is rotated to this change's merge commit; Verjson/verjson-cli-projects#159 is the single bridging pull request.

## Generated headers record every output-affecting option

`gen-changelog-caller.sh` `contract-test` and `pr-gate` headers now record every option that changed the file, as the release modes already did. Regenerating any member from its `# Generated by` header alone now reproduces it byte for byte: before this, verjson-cli's `--release-caller-package-dirs` and verjson-cli-cloud's `--node-version 24.18.0` were lost from the contract test's header. The generated contract test accepts the `--untrusted-runner` option that the PR gate's header can now carry. Adopters pick up the new header and contract-test bytes when they regenerate the set at the next release.
