title: Implement constrained same-run build artifact sharing
---
Adds an opt-in typed `buildArtifact` contract to canonical Node CI callers. Trusted preflight validates policy, participant plans, checkout identity, and compatible build profiles before selecting sharing. A trusted producer exports a bounded same-run ArtifactSet; credentialless consumers run the remaining checks in isolation and emit receipts bound to the ArtifactSet ID and digest. Fallback lanes retain their original plans and aggregate by job result without artifact receipts.

Admission fails closed on rebuild lifecycle hooks, unresolved package-manager calls, nested pnpm/Yarn invocations, nested npm arguments, package-manager execution-shell overrides, npm workspace/config redirection, shell expansion, unsupported wrappers, local executable paths, task runners, and direct commands outside the explicit check-tool allowlist. Tracked `.npmrc` workspace selection, including quoted workspace keys, forces per-lane execution. For pull requests, preflight and producer/consumer authorization require the candidate `.github` tree to match the event base; changes to workflows or local actions use per-lane builds until merged. Credentialless npm checks force `script-shell=/bin/sh` after caller-requested environment removals, so project configuration and `unsetEnv` cannot replace the shell used for admitted work. Newlines are command separators; shell redirection, pathname expansion, shell grouping, carriage returns, non-ASCII characters, and unsupported control whitespace are rejected. Only explicitly supported read-only command forms and options are admitted; unknown flags, output and cache destinations, snapshot updates, formatter writes, linter fixes, and positional mutating subcommands force per-lane execution. Vitest admission is limited to a bare CI-mode invocation or explicit `run`, with no extra options. Whitespace-only script-plan values use a static per-lane fallback. Direct TypeScript checks remain per-lane because configurable incremental build metadata may write under exported roots; positional mutators such as `mocha init` and `tap plugin add` are not admitted. Only top-level ArtifactSet roots mount read-only; nested output roots use per-lane fallback so sibling sources and tests remain visible. The trusted helper mount is conditional on producer or consumer role; ordinary and fallback jobs do not require it.

The adopter policy table remains empty. Hosted Bubblewrap/AppArmor loopback and external-egress behavior, an outside-Verjson canary, and runner-minute savings remain unverified and unclaimed. The release workflow's runner-isolation digest was refreshed because the analyzer report binds the full checkout tree; no release workflow behavior changed.
