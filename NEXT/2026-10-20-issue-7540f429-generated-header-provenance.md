title: Generated headers record every output-affecting option
---
`gen-changelog-caller.sh` `contract-test` and `pr-gate` headers now record every option that changed the file, as the release modes already did. Regenerating any member from its `# Generated by` header alone now reproduces it byte for byte: before this, verjson-cli's `--release-caller-package-dirs` and verjson-cli-cloud's `--node-version 24.18.0` were lost from the contract test's header. The generated contract test accepts the `--untrusted-runner` option that the PR gate's header can now carry. Adopters pick up the new header and contract-test bytes when they regenerate the set at the next release.

`scripts/ci-gate/generator-header-provenance.test.py` reads every mode from the generator's usage line. For each mode it generates the file with all of its options, regenerates from the parsed header alone, and requires byte identity. Default invocations keep their bare `<mode> <sha>` header. The two runner-isolation backlog digests that bind the generator's bytes are re-pinned from the checker.

`scripts/contract-version.py verify` now reads the generator header shapes that do not name the hub on their line: `# CONTRACT_REF=<sha>`, `# Contract: <sha>`, and the `# scripts/gen-<name>.sh [<mode>] <sha>` regeneration line. Before this, a stale SHA in one of those alone passed `verify` (for example line 3 of a generated `ai-review-label-rearm.yml`). The test suite runs every SHA-stamping `scripts/gen-*` generator and requires every SHA it stamps into a comment to be read back. ADR 0191 records the restored invariant.

The generated `container-candidate-contract.test.sh` now requires every image's `provenance.builderIdentity` to be exactly `Verjson/.github/.github/workflows/container-candidate-publish.yml@<contract>`. A stale or wrong identity fails in pull-request CI, rather than after building and publishing. Its header also records the regeneration command with the config path. ADR 0216's 2026-10-20 amendment explains why the generated test, not `contract-version.py`, owns the check.

The generated contract test now compares the whole PR gate to the bytes `pr-gate` writes at its pin for the runner its header records: `ubuntu-24.04` by default, or exactly the recorded `--untrusted-runner` labels in order. Any other runner, a header over a different body, an added job, an edited trigger, or a YAML merge key therefore fails (ADR 0165 amendment). The comparison binds the selection but does not prove a self-hosted label is ephemeral. The `builderIdentity` check is proven to be exact rather than a prefix or suffix match. The header-provenance test requires every generator option to be exercised. `contract-version.py` reads header hex case-insensitively and normalizes claims to lowercase.
