title: Reach guards that no test fixture reached
---
Tests now reach 22 fail-closed guards in the merge-gate, platform, and changelog-release suites that no fixture reached before, and each test checks that guard's own error. Before this change, deleting any of these guards left every test green: an earlier check rejected the fixture first, or no test exercised the guard at all. The one exception is the App-approval guard, whose wrong-identity and stale-approval cases already caught its deletion; only its missing-approval case was hollow. Each new or corrected fixture passes every earlier check, so deleting its guard now fails its test.

- Merge gate: the local-caller run-attempt replay guard in `verify-arm-receipt.sh`, the GraphQL `errors` check on disabling auto-merge in `gate-rearm.yml`, and the exact-head App-approval guard in `ai-privileged-merge.yml`.
- Platform: the duplicate-secret check in `app-key-environment-audit.py` and its six metadata guards (page, collection, and identity shape; repository format; default branch; owner type). Also the object, array, and single-page guards in `actions-paused-drift.py`, the hosted-runner collection-type check in `runner-admission-reconcile.sh`, and the candidate and stack-profile validation in `gen-renovate-compatibility-caller.sh`.
- Changelog release: the destination-receipt digest check in `container_release_manifest.py`, the owner-namespace check in `container_registry_destinations.py`, and the key-format and existing-destination guards in `container_dependency_transfer.py`. Tests also now execute the exact-head proposer guard that `gen-changelog-caller.sh` emits into the `release-artifact` and `release-snapshot` callers, instead of only matching its step text.
- Still open on #1995: the guards in the contract tests generated by `gen-container-candidate.sh` and `gen-container-release.sh` belong to the container contract suites that #1997 is rewriting. The runner-id type check in `runner-admission-reconcile.sh` is an equivalent mutant: without it, jq's `floor` type error rejects the same input on the same path.
