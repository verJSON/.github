title: Give generated release callers' package token only to exact private downloads
---
Security fix: the release callers that `scripts/gen-changelog-caller.sh` generates no longer give `NODE_AUTH_TOKEN` to `npm ci --ignore-scripts`. This covers the `verify` job of release-node, release-snapshot, and release-artifact, and release-artifact's `acquire-private-dependencies` job. Under npm 10.9.9 and 11.19.1, a git dependency's own `.npmrc` received the token in every one of them, and under npm 10 linked and git dependencies also ran `prepare` with it. Every credentialed install now runs `scripts/npm-private-acquisition.sh`, the acquisition `node-release.yml` already used and now runs from the same file. It is checked out at the immutable contract commit and only `npm cache add`s sha512-verified locked `npm.pkg.github.com` downloads. A tokenless `npm ci --ignore-scripts --prefer-offline` then installs the tree from that cache. The generated contract test pins the new steps, and `scripts/release-caller-credential-isolation.test.py` runs them under both npm majors against a hostile git dependency. The contract test now pins release-artifact's whole acquisition job: settings, step sequence, actions, environments, and run bodies. Both jobs also refuse a release tree that carries `.verjson-npm-acquisition-contract`, and `verify` refuses one that carries `.changelog-contract` before checking out the selection contract. In release-artifact, the shared acquisition script itself now enforces the approved-package list through `APPROVED_PRIVATE_PACKAGES`. It refuses any locked GitHub Packages download whose package name is not approved before npm runs, so every credentialed fetch is approved by construction. The contract test compares both allowlist values exactly as parsed, so a comment can no longer stand in for a widened list, and the script runs only from `$GITHUB_WORKSPACE`. node-release and the verify jobs set no list and trust the caller's lockfile. As defense in depth, the release-artifact lock validation also refuses `npm-shrinkwrap.json`, a resolved root lock entry, a private download outside `node_modules/`, non-ASCII or trailing-dot hosts, and a `resolved` URL that WHATWG parsing would rewrite, and it treats npm aliases like their target. The acquisition job's `name`, `needs`, `if`, `runs-on`, and `timeout-minutes` values are pinned, and the verify job may no longer add settings such as `container:`. Adopters, including this repository's own `.github/workflows/release.yml`, get the fix only when their callers are regenerated at a contract commit that contains it. See ADR 0220's second 2026-10-18 amendment.
