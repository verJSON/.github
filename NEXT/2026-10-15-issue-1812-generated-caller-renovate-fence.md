title: Renovate maintains generator action pins so adopters stop hand-editing generated callers
---

`renovate.json` gains a regex custom manager over `scripts/gen-*.sh|py` that reads every `release_*='owner/repo@<sha> # <tag>'` pin declaration in the changelog caller generator, with the `github-actions` manager's datasource and versioning. Renovate now proposes those digest bumps here, in the same grouped `github actions digests` PR as this repository's workflows, instead of in adopters' generated callers. The generator declares each pin once: the pr-gate caller expands the declaration (its bytes are unchanged), and the generated contract test passes `EXPECTED_RELEASE_CHECKOUT` and `EXPECTED_RELEASE_SETUP_NODE` to its release-shape check, whose approved pre-credential step digest now records which declared pin a step uses rather than the pin's value, so an automated bump stays green.

The generator and this repository's workflows move to `actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1` (v7, v7.1.0), `actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9` (v7.0.2), and `actions/download-artifact@9000827ccba6bdab643e8b6fd33ac0654aef8333` (v8.0.2), each resolved from its upstream tag. Adopters pick these up when they regenerate at the merge commit. Two files keep their pins: this repository's own generated `release.yml`, which follows its contract pin, and `runner-canary.yml`, which verjson-cli-cloud accepts by exact content digest.

`renovate/generated-callers.json` is a Renovate preset that disables the `github-actions` manager for the generated `.github/workflows/release.yml` and `.github/workflows/changelog-contract.yml`, the generator-owned paths whose output holds a dependency the manager would update (ADR 0232). The organization preset in Verjson/renovate-config is to extend it as `github>Verjson/.github//renovate/generated-callers` (Verjson/renovate-config#59); this repository's `renovate.json` already extends it, so its own generated `release.yml` is fenced now. `renovate.json` also disables the `github-actions` manager for `runner-canary.yml`, which verjson-cli-cloud accepts by exact content digest.

`scripts/ci-gate/renovate-generated-callers.test.py` (platform group) derives the fenced path set by generating every mode the changelog generator accepts, requires every other generator to emit nothing Renovate reads, and proves that the manager extracts exactly the declared pins, that no generator carries a pin it cannot move, that a generator renovated by the manager's own replacement still passes the generated release-shape contract for every release mode, and that the generator's pins match every pin of the same action in this repository's workflows, outside exceptions that are themselves fenced. Registered rejection cases prove the generated release-shape check still binds exact commits now that its digest does not: a verify checkout or setup-node step moved off its declared commit, and an empty, unpinned, or wrong-owner `EXPECTED_RELEASE_*` value, each with its own diagnostic.
