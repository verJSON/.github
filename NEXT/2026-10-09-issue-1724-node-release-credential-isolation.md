title: Isolate Node release registry credentials from lifecycle scripts
---

The canonical Node release workflow now confines credentialed acquisition, lifecycle scripts, metadata preparation, version stamping, build, and packing to a read-only preparation job. A fresh GitHub-hosted publisher validates the transferred archives against package identities and versions read from the immutable tag, checks archive digests and paths, then publishes with scripts disabled. The publisher and retention jobs cannot reuse a self-hosted preparation runner. Contract tests cover credential boundaries, artifact tampering, real npm pack output, and npm package-map keys matching packed metadata. The publisher checks the exact prepared artifact ID and its 2 GiB size before download, including failed-job reruns; upload compression is disabled for already-compressed tarballs so that limit bounds extracted data. The npm cache path is configured before setup-node so the bounded cache check and cleanup apply to the cache npm actually populates. Persistent setup-node cache restore/save is disabled when private dependency credentials are supplied, preventing private tarballs from entering a cross-run cache; a temporary versioned marker in the caller workspace invalidates old cache keys and is removed immediately after setup-node. The token-bearing npm install temporarily quarantines the tag-controlled root .npmrc and restores it on success or failure, so registry and auth directives from a release tag cannot redirect NODE_AUTH_TOKEN. Archive validation caps aggregate bytes and rejects oversized PAX and GNU metadata before parsing, including a 4 MiB aggregate limit for accumulated metadata. GNU sparse archives are rejected before tarfile can accumulate extent lists, with regression coverage for GNU and all three PAX sparse formats.

The legacy `runner` input remains accepted for compatibility but is ignored; every Node release job requires a fresh GitHub-hosted `ubuntu-24.04` runner and checks `runner.environment` before any other step, so a self-hosted runner cannot impersonate the hosted label. The preparation job masks `NODE_AUTH_TOKEN` at job scope and exposes it only to `npm ci --ignore-scripts`; lifecycle scripts, metadata preparation, builds, and packing run without the token.
